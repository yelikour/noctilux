# Agent Handoff

This document is the handoff checklist for agents and contributors working on Noctilux.
It records the current project state, operating rules, validation commands, and known release history.

## Project Scope

- Noctilux is a general offline image batch processing and augmentation toolkit.
- It is not an AIGC-specific project.
- It is not a model training framework.
- The project focuses on pre-training image preparation, reproducible pipelines, safe outputs, and metadata traceability.

## Current Feature Overview

CLI commands:

- `noctilux run`: execute configured offline batch processing jobs.
- `noctilux preview`: generate a single-image preview grid from configured pipelines.
- `noctilux report`: read run metadata and generate a lightweight Markdown report, with optional CSV summary.
- `noctilux make-manifest`: scan an image folder and create a manifest CSV.
- `noctilux inspect-config`: validate and summarize a YAML config without processing images.
- `noctilux list-transforms`: list registered transforms.

Internal annotation status:

- `noctilux.annotations` contains schema dataclasses, prototype COCO/YOLO readers and writers, bbox resize/flip/crop geometry helpers, and minimal run integration helpers.
- v0.8.0 wires experimental opt-in COCO bbox-only annotation IO into `noctilux run` for selected transforms. Image-only configs remain the default and existing metadata schema fields remain unchanged.
- v0.8.1 adds guardrails: annotation IO rejects resume, skip-existing, retry-failed, and parallel execution; output_path must differ from input_path; unsupported transform and unmatched sample warnings appear in run summary; annotations.enabled=false bypasses sub-field validation.
- v0.9.0 exposes crop_window metadata in transform log for all crop transforms (center_crop_ratio, random_crop_ratio, square_crop, random_resized_crop). Crop transforms write crop_window to the context dict; pipeline reads it into the log entry. Annotation crop bbox sync is not yet implemented.

Current transform categories:

- Compression: JPEG, WebP, PNG resave, double JPEG compression.
- Resize: long edge, short edge, exact resize, downscale/upscale.
- Crop: center crop ratio, random crop ratio, random resized crop, square crop.
- Geometric: horizontal flip, vertical flip, rotate.
- Blur: Gaussian blur, median blur, motion blur.
- Noise: Gaussian noise, Poisson noise, salt-and-pepper noise.
- Color: brightness/contrast, gamma correction, saturation/hue, grayscale, sharpen, posterize.

Metadata output structure from `noctilux run`:

- `manifest.csv`: per-output record with original path, output path, pipeline, sizes, formats, seed, success, and error fields.
- `transform_log.jsonl`: per-output transform execution details, including actual sampled parameters and `applied` state.
- `failed_images.csv`: failed sample records with pipeline, repeat index, seed, stage, and error.
- `summary.csv`: per-pipeline totals, successes, and failures.
- `report.md`: optional report generated later by `noctilux report` from existing metadata.
- `summary_report.csv`: optional CSV summary generated by `noctilux report`.

## Directory Map

- `src/noctilux/`: package source, CLI, config loading, scanning, pipeline execution, saving, metadata, preview, report, and worker logic.
- `src/noctilux/annotations/`: annotation schema, parser/writer prototypes, bbox geometry helpers, and v0.8.0 minimal COCO bbox-only run integration.
- `src/noctilux/transforms/`: registered transform implementations grouped by domain.
- `configs/examples/`: runnable example configs, including `quickstart_sample.yaml`.
- `configs/presets/`: reusable preset pipeline configs for common offline augmentation workflows.
- `docs/`: user docs and this handoff document.
- `tests/`: pytest suite covering config, scanner, transforms, pipeline, metadata, CLI, preview, report, and project quality checks.
- `examples/images/sample.jpg`: tracked synthetic sample image for quickstart, preview, CI, and smoke tests.
- `outputs/`: ignored runtime output directory; do not commit it.

## Development Rules

- Do not force push.
- Do not force-push, move, or delete tags.
- Do not move the `v0.3.0` tag.
- Do not commit `outputs/`.
- Do not commit caches, virtual environments, temporary files, or large local assets.
- Do not convert the project into an AIGC-specific tool.
- Do not rewrite core architecture without an explicit plan and user approval.
- New features must include tests.
- After changes, run pytest and ruff before declaring completion.
- Keep dependencies minimal; do not add OpenCV, Albumentations, AugLy, or imagecorruptions unless the user explicitly asks for a scoped backend change.
- Do not implement parallel execution without first completing the metadata-safe writer refactor (v0.5.1). See `docs/parallel_resume_design.md` for phased plan. Parallel execution is available as experimental / hardening-stage (v0.5.3+). Changes to worker/result/metadata paths must be made cautiously and must run `tests/test_parallel.py` plus resume and smoke checks.
- Annotation integration is experimental. Changes to `run`, `pipeline`, transform logs, or annotation geometry must run `tests/test_annotation_integration.py` plus the annotation parser/geometry/writer tests.

## Common Smoke Test

```bash
rm -rf outputs/quickstart_sample

noctilux run --config configs/examples/quickstart_sample.yaml

noctilux preview \
  --config configs/examples/full_v020.yaml \
  --image examples/images/sample.jpg \
  --output /tmp/noctilux_preview.jpg \
  --max-pipelines 4 \
  --seed 42

noctilux report \
  --metadata outputs/quickstart_sample/metadata \
  --output outputs/quickstart_sample/report.md \
  --csv-output outputs/quickstart_sample/summary_report.csv \
  --overwrite
```

## New Agent Onboarding Flow

1. Read `README.md`, `PROJECT_GUIDE.md`, `CHANGELOG.md`, and `docs/agent_handoff.md`.
2. Run `git status`, `python -m pytest`, and `ruff check src tests scripts`.
3. Execute the user-specified task with the smallest sufficient scope.
4. Do not proactively expand the scope beyond the user request.
5. Before final response, verify the worktree, tests, lint, tags, and CI status when relevant.

## Handoff Output Template

Use this structure when handing work back to the user or the next agent:

- Modified files.
- Implemented changes.
- Test results.
- Ruff results.
- Commit hash.
- Tag status.
- CI status.
- Residual risks.
